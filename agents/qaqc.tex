\section{Purpose and scope}

\begin{itemize}
\item Define a repeatable checkout of every new PACMAN card before it goes into a production system or onto an
  ASIC test stand.
\item Two utilities, both run on the PACMAN's own Linux system:
  \begin{itemize}
  \item \texttt{pacman\_lnxcheck}: the standard embedded-Linux checkout of the Trenz module (CPU, memory,
    on-chip supplies, Ethernet, flash and SD storage).
  \item \texttt{pacman\_hwcheck}: the PACMAN-specific test suite (power, tile I/O, timing, analog paths, front
    panel):  tests chosen on the command line, one run per test card.
  \end{itemize}
\item Firmware validation (Section~\ref{sec:firmware}), separately: once per firmware release, against stated
  requirements, in simulation and on a bench Trenz module.  It qualifies the firmware package, not a card.
\item Scope: the features needed for normal operation.  Features that normal operation does not use are listed
  (Section~\ref{sec:status}) but not tested.
\item Method: wherever possible a feature is tested by loopback, so that the feature and its feedback path are
  verified together, and a failure points at hardware, firmware or software.
\end{itemize}

\section{Production setting}

\begin{itemize}
\item PACMAN 1v5 with a Trenz TE0720 module (Zynq-7000).  The card boots from its microSD card (boot image and
  Linux root file system) and is reached over Ethernet only (\texttt{ssh}).  Production cards have no USB/JTAG
  header installed.
\item \textbf{ASIC protection jumper (J5).}  Installed whenever the card is in the production system or connected
  to ASICs.  The checkout runs with J5 \emph{removed}; with J5 installed, \texttt{pacman\_hwcheck} refuses
  everything except its read-only report.
\item The PACMAN data and command servers are stopped during the checkout (they share the data path with the
  loopback test) and restarted afterwards.
\end{itemize}

\section{The utilities}

\subsection{Common conventions}\label{sec:conventions}
\begin{itemize}
\item One line per result: \texttt{<VERDICT> <name>---- <value>}, then a final \texttt{VERDICT} line.
\item Result verdicts: \texttt{PASS}, \texttt{FAIL}, \texttt{SKIP} (not done, with the reason),
  \texttt{INFO} (recorded, not judged).  \texttt{pacman\_hwcheck} also prints \texttt{DATA} lines (sweeps).
\item Run verdict and exit code:
  \begin{center}
  \begin{tabular}{@{}lll@{}}
  \toprule
  Run verdict & Meaning & Exit code \\
  \midrule
  \texttt{PASS} & every check passed, nothing skipped & 0 \\
  \texttt{FAIL} & at least one check failed & 1 \\
  \texttt{INCOMPLETE} & no failure, but something was skipped & 2 \\
  (refused / usage) & bad options, or J5 installed & 3 \\
  \bottomrule
  \end{tabular}
  \end{center}
\item Only a \texttt{PASS} run qualifies a card.
\end{itemize}

\subsection{\texttt{pacman\_hwcheck}: PACMAN hardware}

A test suite, not one checkout:  the tests are chosen on the command line, can be combined, and always run in the
order below.  Each test card gets its own run, with \opt{tile\_mask} set to the tiles that carry it; tiles outside
the mask are skipped.  Every test leaves the board as it found it (tile enables restored, DACs at 0, MUX open).

\begin{center}
\begin{tabularx}{\linewidth}{@{}lL>{\raggedright\arraybackslash}p{2.6cm}@{}}
\toprule
Test & Checks & Needs \\
\midrule
\opt{read\_only} & Firmware and hardware versions, build information, J5 state, board and tile monitors, data
  path status.  The only test allowed with J5 installed. & -- \\
\opt{power} & Board rails against nominal; 3V0 off, then on.  Each tile in the mask in turn: VDDA and VDDD
  swept over the DAC range into the card's loads (floor, gain, swing, monotonic, load), the other tiles checked off. &
  loopback test card (loads) \\
\opt{loopback} & Each tile in turn, only that tile enabled: random data on its four UARTs through the card, words
  received, bit errors, receiver error counters; no stray data on other UARTs. & loopback test card \\
\opt{atc\_outputs} & Each tile in turn: pulses on its G (SYNC) and H (TRIG) outputs, counted as words on its PISO
  inputs 0 and 1 (none with the tile masked). & ATC test card \\
\opt{lemo\_inputs} & Rates on the TRIG (LEMO A) and PPS (LEMO B) inputs, counted by the firmware over 1 s: 1 kHz
  $\pm$20\% each (link alive). & 1 kHz TTL on both (tee) \\
\opt{ana\_mon} & Each tile in turn: its clock on the analog monitor, into the ADC (100\,$\Omega$), then from the
  front panel through the MUX loop resistors (series, swapped, divider P, divider N). & ATC test card \\
\opt{adc} & ADC registers; the test DAC into the ADC through the MUX, directly and through both series loops. &
  -- \\
\opt{blink} & The Trenz red LED, then PACMAN LED-0 to LED-3, in turn; the operator watches. & operator \\
\opt{sma} & The MUX puts R28 across the SMA jacks J1001 (P) and J14 (N): 100\,$\Omega$ $\pm$20\% on a DMM (the
  reading includes the MUX switches); the MUX is opened after. & operator, DMM \\
\opt{i2c\_stress} & Sweeps of safe transactions over every I2C device (both MUX chips, both DACs), stopping at the
  first error; the I2C clock rate is reported. & -- \\
\bottomrule
\end{tabularx}
\end{center}

\begin{itemize}
\item Modifiers: \opt{tile\_mask} \texttt{M} (bit $t$ = tile $t+1$; default \texttt{0x3ff}), \opt{no\_pause}
  (\opt{blink} blinks for a fixed time, \opt{sma} sets the MUX and then opens it); development: \opt{ber\_bits}
  (loopback length), \opt{sweeps} (\opt{i2c\_stress}), \opt{no\_i2c} (everything on I2C skipped).
\item \opt{blink} and \opt{sma} pause for the operator but take no answer: the run's verdict counts only the
  checks the program makes, and the operator records what was seen.
\item \opt{lemo\_inputs} starts at once: the source must already be on both inputs.  Each input is identified by
  unplugging the other (one input at 0\,Hz).
\item The same tests are a submenu of \texttt{pacman\_menu} (Linux and bare metal):  one entry per test on the
  menu's tile mask, each printing its result lines, without a run verdict; with J5 installed only the read-only
  report runs.
\item The I2C bus runs at 100\,kHz by default (needed on at least one hw1v4 card with its cable).
\item Safe MUX layer: every MUX setting goes through \texttt{iic\_set\_mux\_to\_front\_panel},
  \texttt{iic\_set\_mux\_to\_adc}, \texttt{iic\_set\_mux\_loop} and \texttt{iic\_set\_mux\_open}.  Each common
  (front panel, ADC) is set on its own, with at most one source; the state is read back from both MUX chips.  A
  setting the layer refuses (for example a 100\,$\Omega$ termination on a source already terminated on the other
  common, which would then see 50\,$\Omega$) changes nothing and is returned to the program, which decides what to
  do; the drivers do not open the MUX on their own.  The test DAC reaches the tiles only through the MUX, so it is used only with the
  MUX set this way.
\item MUX loops (\texttt{iic\_set\_mux\_loop}, five fixed patterns only):  the two 100\,$\Omega$ resistors join switch
  14 (and 15) of the P chip to the same switch of the N chip, and each end can go to either common; switch 16 is
  ground.  Series: the source on the front panel, each resistor from one front-panel side to the other ADC side (the
  ADC sees the pair inverted).  Divider P (N): one side of the source through one resistor, the other resistor to
  ground, the ADC across it.  Every front-panel switch is so checked without an operator.  The fifth pattern puts
  R28 alone across the front-panel jacks (\opt{sma}).  The tied switch 11 is never used.
\end{itemize}

\section{Firmware validation}\label{sec:firmware}

\begin{itemize}
\item Once per firmware release (official or candidate), before it is installed on production cards.
\item Two stages, against one list of requirements:
  \begin{itemize}
  \item \textbf{Simulation} (\texttt{make check}, GHDL): every requirement.
  \item \textbf{Hardware} (\texttt{pacman\_fwcheck}, on a bench Trenz module running the release): the
    requirements that can be checked on the board with no tiles and no external signals.
  \end{itemize}
\item The requirements (\texttt{pacman-firmware/docs/requirements.txt}) and \texttt{pacman\_fwcheck}
  (\texttt{pacman-software}, with the pacman-apps) are reviewed by hand;  the GHDL checks are written and kept by
  the PACMAN agents (\texttt{pacman-firmware/ghdl/agents}).
\end{itemize}

\subsection{Requirements}

\begin{itemize}
\item Source: \texttt{pacman-firmware/docs/requirements.txt}; listed in Appendix~\ref{app:requirements}.
\item Three levels:
  \begin{itemize}
  \item Level 1 (\texttt{RX-1}): what a unit promises, for a human to read.
  \item Level 2 (\texttt{RX-1.1}): a testable statement, backed by checks.
  \item Level 3: the individual checks of the GHDL check benches (\texttt{check/*\_check.vhd}), each counted under
    the level-2 requirement in force, set in the bench with \texttt{req("RX-1.1")}.
  \end{itemize}
\item Each level-2 requirement is marked \texttt{sim} (simulation only: internal timing, reset, pins, external
  inputs) or \texttt{sim+hw} (also checked on the board by \texttt{pacman\_fwcheck}).
\end{itemize}

\begin{center}

\midrule

\subsection{Simulation: \texttt{make check}}

\begin{itemize}
\item Run in \texttt{pacman-firmware/ghdl/agents}: \texttt{make check} (GHDL; about 20~s).  Five check benches
  (Global, TX, RX, Timing, and the register bus across all units), 3300 checks.
\item Output: one line per bench, then one line per requirement, under its level-1 heading:
\begin{verbatim}
PASS rx_unit_check (671 checks)
...
  REG-2    Registers hold what is written, independently.
    PASS REG-2.1    161  sim+hw  Every read/write register reads back every value
                                 written to it, all bits.
...
---- 53 requirements, 53 with checks, 3300 checks in all, 0 to look at
\end{verbatim}
\item Per requirement: \texttt{PASS}, \texttt{FAIL} (a check failed), or \texttt{NONE} (no check backs it).  Also
  flagged: requirement IDs not in \texttt{requirements.txt}, and checks made before any \texttt{req()}.
\item Pass: every bench \texttt{PASS}, every requirement \texttt{PASS}, \texttt{0 to look at} (exit code 0).
\end{itemize}

\subsection{Hardware: \texttt{pacman\_fwcheck}}

\begin{itemize}
\item Checks the 30 \texttt{sim+hw} requirements in the installed firmware.  One source, two builds: Linux (one of
  the pacman-apps, in the image) and bare metal (JTAG).
\item Method: the firmware's own loopback.  DMA packets go out through the TX unit, back in through RX input 2
  (internal loopback) and out through DMA; masks, all 40 channels, every bit, 1000 random packets, frame length,
  headers, packet size and timeout.  Also: register read-back and crosstalk, broadcast writes, timeouts, the
  timestamp rate, the test pattern, heartbeat and marker words, the timestamp restart (marker~0), and the timing unit's counters (pokes routed
  to the markers only).
\item Safety: only the read-only checks run with J5 installed, with tile power or any tile enabled, with
  \opt{read\_only}, or (Linux) while a PACMAN server runs.  Every register written is saved and restored, also on
  Ctrl-C or kill.  Not restored: the counters, the timestamp (marker~0 restarts it) and the DMA rings (the servers set
  them up when started).  Nothing leaves the PL.
\item Output: failed checks as they happen (all checks with \texttt{-v}), then one line per requirement
  (\texttt{PASS}, \texttt{FAIL}, \texttt{NONE}: not checked) and a \texttt{VERDICT} line; verdicts and exit codes
  as the other utilities (Section~\ref{sec:conventions}).  A read-only run is \texttt{INCOMPLETE}.
\begin{verbatim}
PASS REG-2.1    54  every read/write register reads back every value written
...
VERDICT PASS  (30 requirements:  0 failed, 0 not checked;  0 failed checks)
\end{verbatim}
\item Run on Linux (about 0.2~s):\\
  \texttt{/etc/init.d/pacman\_server stop; pacman\_fwcheck; /etc/init.d/pacman\_server start}
\item Bare metal (from the top of \texttt{pacman-software}): \texttt{xsct apps/fwcheck/install.tcl}, then
  \texttt{xsct run.tcl} in \texttt{fwcheck/} (resets the board; output on the console).
\end{itemize}

\subsection{Release procedure}

A firmware release is validated when, for that release:
\begin{enumerate}
\item \texttt{make check} passes (all 53 requirements);
\item \texttt{pacman\_fwcheck} gives \texttt{VERDICT PASS} on a bench Trenz module running the release's
  bitstream, under Linux and on bare metal.
\end{enumerate}
The three outputs are kept with the release.  First result (3.6.0 candidate, git 13dc480, 2026-10-17): all
pass.

\subsection{Coverage}

\begin{itemize}
\item The 23 \texttt{sim} requirements are checked in simulation only: they concern internal timing (register bus
  timing, UART phase and delay), reset, the board pins (tile enables, LEDs, G and H outputs), the LEMO inputs and
  the receiver's tolerance of real lines (glitches, frame errors, stalls).  On each card, \texttt{pacman\_hwcheck}
  covers the tile enables, LEDs and LEMO inputs, and (\opt{atc\_outputs}, \opt{ana\_mon}) the G and H tile outputs and CLK.
\item The simulation is of the firmware sources, the hardware check of the built bitstream: together they cover
  the build as well as the design.
\end{itemize}

\section{Shifter's guide: hardware checkout}

For an operator who runs the checkout the standard way.  Items marked \tbd{\ldots} are still to be filled in.

\subsection*{You need}
\begin{itemize}
\item The PACMAN card with its microSD card (production image), and its serial number \tbd{where printed}.
\item The loopback test card and the ATC test card, DMM, 1 kHz TTL source with a tee, a J5 jumper, Ethernet
  cable, PACMAN power supply.
\item A PC on the same network, with \texttt{ssh}.
\end{itemize}

\subsection*{Prepare}
\begin{enumerate}
\item Power off.  Remove J5 (ASIC protection jumper).  Make sure no ASICs are connected.
\item Install the loopback test card on the tile connectors.
\item Connect the 1 kHz TTL source to the TRIG and PPS LEMO inputs (tee).
\item Connect Ethernet; power on.  Wait about \tbd{N} s for Linux to boot.
\item Log in: \texttt{ssh \tbd{user}@\tbd{PACMAN address}}.
\item Stop the PACMAN servers:  \texttt{/etc/init.d/pacman\_server stop}
\end{enumerate}

\subsection*{Run}
\begin{enumerate}
\item Linux checkout (a minute or less):\\
  \texttt{pacman\_lnxcheck -{}-server \tbd{TFTP server} | tee lnxcheck-<serial>.txt}
\item With the loopback test card:\\
  \texttt{pacman\_hwcheck -{}-read\_only -{}-power -{}-loopback -{}-lemo\_inputs -{}-adc -{}-i2c\_stress
  | tee hwcheck-loopback-<serial>.txt}
\item Power off, swap to the ATC test card, power on, log in, stop the servers, then:\\
  \texttt{pacman\_hwcheck -{}-atc\_outputs -{}-ana\_mon | tee hwcheck-atc-<serial>.txt}
\item Operator tests:\\
  \texttt{pacman\_hwcheck -{}-blink -{}-sma | tee hwcheck-operator-<serial>.txt}
  \begin{itemize}
  \item \opt{blink}: watch the Trenz red LED, then PACMAN LED-0 to LED-3, light in turn; write down what you saw.
  \item \opt{sma}: put the DMM (resistance) across the SMA jacks J1001 and J14; write down the reading
    (100\,$\Omega$ $\pm$20\%), then press Enter.
  \end{itemize}
\item LEMO inputs, each alone: unplug PPS and run \texttt{pacman\_hwcheck -{}-lemo\_inputs} (TRIG near 1 kHz,
  PPS 0); then the other way round.  Write down both results.
\end{enumerate}

\subsection*{Read the result}
\begin{itemize}
\item The last line of each run is the verdict.
\item \texttt{PASS} from every run: the card passes.
\item \texttt{FAIL}: the lines marked \texttt{FAIL} say what failed.  Do not repeat blindly: record, and report to
  \tbd{contact}.
\item \texttt{INCOMPLETE}: something was skipped (lines marked \texttt{SKIP} give the reason).  Fix the setup
  and run again.
\item \texttt{REFUSED} with J5 mentioned: J5 is installed; power off, remove it, start again.
\end{itemize}

\subsection*{Finish}
\begin{enumerate}
\item Copy the result files to \tbd{results location}, named by serial number.
\item Restart the servers (\texttt{/etc/init.d/pacman\_server start}) or reboot.
\item Power off; remove the fixtures.  Install J5 before the card goes to a production system or ASICs.
\item Record the card's status in \tbd{tracking sheet}.
\end{enumerate}
